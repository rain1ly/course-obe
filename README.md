# 达成度 · CourseOBE

**把教师每学期要做一次的课程目标达成度评价，从 4 小时的 Excel 手工，变成 12 分钟。**

课程目标达成度智能分析工作台 · 2026 第九届传智杯 AI 创新应用挑战赛（个人赛 · B 组）

---

## 它解决什么问题

工程教育认证与本科教学评估要求每门课做「课程目标达成度评价」，流程是：

课程大纲定若干课程目标 → 每道考题映射到目标 → 按学生得分算各目标达成度 → 写持续改进报告。

现状是 Excel 手工完成：3–5 个目标、数十个考核点、上百名学生，一门课 **2–6 小时**，每学期重来一遍。

最耗神的不是算数，而是「这道题到底考的是哪个目标」这个主观判断——而且不同教师做出来的结果不可比。

## 怎么解决

关键设计：**AI 不做计算。**

| 环节 | 由谁完成 | 为什么 |
|---|---|---|
| 题目 ↔ 课程目标的语义映射 | 大模型，输出置信度与原文依据 | 这是语义判断，规则写不完 |
| 低置信度项确认 | 教师 | 人保留最终解释权 |
| 达成度数值计算 | 确定性纯函数 `core/domain.py` | 必须可审计、可复算、可解释 |

模型给出的是「建议 + 证据 + 把握程度」，不是「结论」。这一点是整个项目的立身之本：
**教师的分数要能被督导组追问到每一道题，模型给不出这种可追溯性，一行可测的算法可以。**

## 快速开始

环境要求：Python 3.10+（开发环境为 3.13）

```bash
git clone <仓库地址>
cd work2

# 1. 建虚拟环境
python -m venv .venv

# 2. 激活（Windows Git Bash / CMD）
source .venv/Scripts/activate
# PowerShell 用：.venv\Scripts\Activate.ps1
# macOS / Linux 用：source .venv/bin/activate

# 3. 装依赖
pip install -r requirements.txt

# 4. 配置密钥（复制模板后填入自己的）
cp .env.example .env
# 编辑 .env，填 OPENAI_API_KEY / OPENAI_BASE_URL / OPENAI_MODEL

# 5. 启动
streamlit run app.py
```

浏览器打开 `http://localhost:8501` 即见首页。

> Windows 用户也可以直接双击项目根目录的 `start.bat` 启动，省去敲命令。

> 换模型供应商只需改 `.env` 里那三行，代码不用动。兼容任何 OpenAI 协议接口。

## 跑测试

```bash
.venv/Scripts/python.exe -m pytest tests/ -v
```

`tests/test_domain.py` 覆盖达成度算法的主要边界：加权、去重、零满分、空输入、分级阈值。
这些测试全绿，是「计算可复现」的直接证据。

## 设计取舍

**1. 为什么不拆前后端，也不用 Next.js**

单人赛、27 天、零代码基础。Streamlit 不需要构建步骤、单文件即出界面、
推 GitHub 就能部署上线。代价是界面精细度上限低一些，换来的是"能跑通、能复现、能演示"。

**2. 为什么让 AI 只做映射，不做计算**

模型不保证确定性，同一个输入两次调用可能给不同数值。而教师必须能解释分数怎么来的。
这个取舍记录在 `decisions/ADR-001-为什么用确定性算法算达成度.md`。

**3. 为什么数据库做得这么浅**

一门课一条记录，结构化数据整体存 JSON。27 天内不值得为关系建模花时间，
而且「删掉 `data/app.db` 就能干净重跑」对评审复现极其友好。
